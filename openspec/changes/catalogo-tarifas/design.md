# Design: Catalogo de Tarifas

File copy of Engram `sdd/catalogo-tarifas/design` (hybrid store).

## Technical Approach

Extend `package_templates` in place (exploration Option 1), ship the real
price list as migration data, and make currency a setting instead of a
constant. Four concerns, deliberately kept apart because they fail
differently: **schema** (a column rename that breaks Supabase string selects
at runtime), **catalog data** (68 literal rows whose only real risk is
transcription), **currency** (one module replacing 11 hardcoded formatters,
touching the verified golden path), and **UI** (picker rework + two ABM
route trees). `client_packages.template_id` is `ON DELETE SET NULL` and
`sales.total` already snapshots price, so history needs no migration at all.

Size budget note: this design exceeds the skill's 800-word guidance,
following the `caja-diaria` precedent (#116) and the orchestrator's explicit
request for the full DDL sketch, call-site enumeration, and module contracts.

## Architecture Decisions

| # | Decision | Chose | Rejected | Rationale |
|---|---|---|---|---|
| 1 | Uniqueness | **Partial** unique index `(zone_id, gender) where active` | Plain `unique(zone_id, gender)` | A total constraint makes archiving permanent: once a tariff is archived, staff can never create a replacement for that (zone,gender) — a guaranteed ABM dead end. Direct precedent in `0003_catalog.sql`: `expense_categories_name_active_idx ... where not archived`. Also resolves the live collision below |
| 2 | The 5 English demo zones | **Archive** zones (`archived=true`) + **deactivate** their templates (`active=false`) in `0012` | Hard-delete them | `body_zones` is referenced `ON DELETE RESTRICT` by `package_templates`, `appointments`, and `client_packages`; a dev DB with `seed-demo` data would fail the delete. Archiving is the project's own posture ("archive, never hard-delete") and drops them out of `listActiveBodyZones` for free |
| 3 | Where the seed lives | Its own migration `0013_seed_service_catalog.sql`, separate from `0012` schema | One migration, per the proposal | Splits slice A into two sub-400 slices (A1/A2) with independent rollback: A2 reverts by deleting seeded rows by name, A1 by reversing the DDL. Different failure modes, different reviews |
| 4 | Transcription safety | One **temp staging table** populated once; zones and templates both derived from it; a `do $$` assertion block verifies row/zone counts before commit | Two hand-written INSERT lists (zones, then templates) | A separate zone list is the transcription bug: a typo in one list silently orphans a template. Deriving `body_zones` from `select distinct area` makes zone/template names identical *by construction*. MINI and GRANDE rows are generated by cross join, cutting 30 literal rows to 17 |
| 5 | Formatter reach | Pure `src/lib/money.ts` + request-cached `getMoneyFormat()` for RSC + a client context provider for client components | Module-level singleton; prop-drilling into every client component | RSC and client components cannot share a module singleton. Server pages call `getMoneyFormat` directly (React `cache()` → one query per request); client components read a context hydrated once by the dashboard layout |
| 6 | Fraction digits | Currency default (EUR → 2 decimals) | Keep `maximumFractionDigits: 0` | 0 decimals was defensible for ARS at 30 000; it is wrong for EUR tariffs at 6 and 10 — `6,50 €` would render `7 €`. Every assertion is being rewritten in slice B anyway |
| 7 | E2E fixture identity | A **real** catalog row (`Axilas`, mujer, pequena, 6 sessions, 10/48) | A synthetic 3-session template on a real zone | A synthetic mujer template on a real seeded zone collides with the seeded mujer tariff under decision 1. Reusing a real row makes the golden path exercise the shipped catalog, and `global-setup` stays self-healing by upserting exactly that row after `resetDatabase` truncates it |
| 8 | Tariff ABM delete | **Archive only** — no hard delete | Delete-then-offer-archive, like `/configuracion/categorias` | `client_packages.template_id` is `ON DELETE SET NULL`, so a delete *succeeds* and silently detaches history instead of raising `23503`. The categorias pattern relies on `RESTRICT` to make delete safe; here it is not. Zones keep the full delete→archive pattern because their FKs *are* `RESTRICT` |
| 9 | Locale column | `clinic_settings.locale text not null default 'es-ES'` | `currency` only, locale inferred | `Intl` needs both; inferring a locale from an ISO code is ambiguous (EUR spans a dozen locales) |

## Migration `0012_service_catalog.sql` (ordered)

```sql
-- 1. Preflight: a price of 0 cannot satisfy the new > 0 checks.
do $$
begin
  if exists (select 1 from package_templates where price <= 0) then
    raise exception 'package_templates has rows with price <= 0; fix or delete them before migrating';
  end if;
end $$;

-- 2. New columns, nullable for now.
alter table package_templates
  add column gender        text,
  add column size_category text,
  add column session_price numeric(12, 2);

-- 3. Rename. NOTE: this does NOT rename package_templates_price_check.
alter table package_templates rename column price to bono_price;

-- 4. Backfill the ~6 live dev/e2e rows (spec: service-catalog req. 2).
update package_templates set
  gender        = coalesce(gender, 'mujer'),
  size_category = coalesce(size_category, 'mediana'),
  session_price = coalesce(session_price, round(bono_price / 6, 2));

-- 5. Lock them down.
alter table package_templates
  alter column gender        set not null,
  alter column size_category set not null,
  alter column session_price set not null;

-- 6. Constraints. The old >= 0 check is replaced by > 0.
alter table package_templates
  drop constraint package_templates_price_check,
  add  constraint package_templates_bono_price_check   check (bono_price   > 0),
  add  constraint package_templates_session_price_check check (session_price > 0),
  add  constraint package_templates_gender_check
       check (gender in ('mujer', 'hombre')),
  add  constraint package_templates_size_category_check
       check (size_category in ('mini','pequena','mediana','grande','cuerpo'));

-- 7. Retire the English demo fixtures BEFORE the partial unique index —
--    'legs' currently carries both seed-demo's "Piernas completas" and the
--    e2e "E2E Golden Path Package", which would collide on (zone, 'mujer').
update package_templates t set active = false
  from body_zones z
 where z.id = t.zone_id
   and z.name in ('underarms','legs','bikini','face','back');
update body_zones set archived = true
 where name in ('underarms','legs','bikini','face','back');

-- 8. One ACTIVE tariff per (zone, gender); archived rows may coexist.
create unique index package_templates_zone_gender_active_idx
  on package_templates (zone_id, gender) where active;
```

`default_sessions int not null check (> 0)` is untouched; slice A2 seeds
every row with `6`. A separate `alter column default_sessions set default 6`
is added in step 6 so ABM inserts may omit it.

## Migration `0013_seed_service_catalog.sql` (seed strategy)

```sql
create table catalog_seed (            -- plain temp-scope staging, dropped below
  area text not null, gender text not null, size_category text not null,
  session_price numeric(12,2) not null, bono_price numeric(12,2) not null);

-- MINI: 11 areas x 2 genders, flat prices -> 13 literals, 22 rows.
insert into catalog_seed
select area, g.gender, 'mini', g.sp, g.bp
from unnest(array['Labio','Mentón','Entrecejo','Patillas','Pómulos','Orejas',
                  'Manos','Nuca','Pies','Línea Alba','Areola']) as area
cross join (values ('mujer',6,30), ('hombre',8,36)) as g(gender, sp, bp);

-- GRANDE: 4 areas x 2 genders, flat prices -> 6 literals, 8 rows.
insert into catalog_seed
select area, g.gender, 'grande', g.sp, g.bp
from unnest(array['Piernas completas (incluye pies)','Brazos completos',
                  'Espalda Completa','Tórax Completo']) as area
cross join (values ('mujer',40,210), ('hombre',50,240)) as g(gender, sp, bp);

-- PEQUEÑA (10, gender-asymmetric), MEDIANA (26, per-area), CUERPO (2):
insert into catalog_seed (area, gender, size_category, session_price, bono_price) values
  ('Perianal','mujer','pequena',15,72),
  ('Axilas','mujer','pequena',10,48),
  ('Ingles Normales','mujer','pequena',10,48),
  ('Ingles Brasileñas','mujer','pequena',15,72),
  ('Ingles Completas','mujer','pequena',25,120),        -- mujer-only
  ('Perianal','hombre','pequena',15,72),
  ('Perfilado de barba','hombre','pequena',15,72),      -- hombre-only
  ('Axilas','hombre','pequena',10,48),
  ('Ingles Normales','hombre','pequena',10,48),
  ('Ingles Brasileñas','hombre','pequena',20,90),
  -- ... 26 MEDIANA rows (mujer 15/78 or 25/120; hombre 20/108 or 30/150 —
  --     note mujer Lumbar is 15/78 while hombre Lumbar is 30/150, so the
  --     tiers do NOT correlate and every MEDIANA row stays explicit) ...
  ('Cuerpo Completo','mujer','cuerpo',80,450),
  ('Cuerpo Completo','hombre','cuerpo',110,600);

-- Transcription guard: fails the migration, not production.
do $$
declare n_rows int; n_zones int; n_dupes int;
begin
  select count(*), count(distinct area) into n_rows, n_zones from catalog_seed;
  select count(*) into n_dupes from (
    select area, gender from catalog_seed group by 1,2 having count(*) > 1) d;
  if n_rows  <> 68 then raise exception 'catalog_seed: expected 68 rows, got %',  n_rows;  end if;
  if n_zones <> 35 then raise exception 'catalog_seed: expected 35 zones, got %', n_zones; end if;
  if n_dupes <> 0  then raise exception 'catalog_seed: % duplicate (area,gender) pairs', n_dupes; end if;
  if exists (select 1 from catalog_seed where session_price <= 0 or bono_price <= session_price)
    then raise exception 'catalog_seed: implausible pricing row'; end if;
end $$;

insert into body_zones (name) select distinct area from catalog_seed
on conflict (name) do nothing;

insert into package_templates
  (zone_id, name, gender, size_category, default_sessions, session_price, bono_price, active)
select z.id, c.area, c.gender, c.size_category, 6, c.session_price, c.bono_price, true
from catalog_seed c join body_zones z on z.name = c.area
on conflict do nothing;

drop table catalog_seed;
```

Two separate statements (staging → zones → templates) rather than one CTE
chain, because a data-modifying CTE's inserts are **not visible** to a plain
table read in the same statement — a `join body_zones` beside an inserting
CTE would silently match zero rows. `drop table` (not `on commit drop`)
keeps this correct whether or not the runner wraps the file in a
transaction.

## `src/lib/money.ts` and how currency reaches the client

export function formatMoney(amount: number, format: MoneyFormat): string;
export function moneyFormatter(format: MoneyFormat): Intl.NumberFormat; // memoized by `${locale}|${currency}`

// src/features/settings/data/money-format.ts — RSC read, one query per request.
export const getMoneyFormat: (s: AppSupabaseClient) => Promise<MoneyFormat>;
//   selects clinic_settings.currency, locale; falls back to DEFAULT_MONEY_FORMAT
//   when the single row is missing (integration suites truncate it). React `cache()`.

// src/components/money-format-provider.tsx — "use client"
export function MoneyFormatProvider(p: { value: MoneyFormat; children: ReactNode }): JSX.Element;

// src/components/money-cell.tsx — "use client"; for TanStack column `cell` renderers,
// which are module-level closures and cannot call a hook directly.

(dashboard)/layout.tsx  ── getMoneyFormat(supabase) ─▶ <MoneyFormatProvider value>

## Golden-path currency resolution

Production default is `EUR`/`es-ES`. `e2e/global-setup.ts` does not rely on
that default: it upserts `clinic_settings` with the exact pair the specs
assert, so the suite survives `resetDatabase` truncating the row.

Assertions become:
- golden-path "6 de 6 sesiones restantes" after the sale, "5 de 6" after completion.
- payment step: `saleAmountPaid = Math.round(48 * 0.6) = 29`, remaining `19`;
  asserts `currencyFormatter.format(19)` → `"19,00 €"`. Both values stay > 0.
- booking step: zone option and `^Paquete Axilas` regex track the renamed constants.
- caja spec: the shortfall assertion becomes the exact `formatMoney(shortfall, {currency:E2E_CURRENCY, locale:E2E_LOCALE})` string instead of a `\$`-anchored regex.

## Harness changes required in slice A1 (all four, same PR)

The rename breaks Supabase string selects at **runtime**, not compile time,
so none of these can be deferred:

1. `tests/integration/helpers/fixtures.ts` — `seedPackageTemplate` params
   `{ zone_id, name, gender, size_category, default_sessions, session_price, bono_price }`;
   the `resetDatabase` TRUNCATE list already covers `package_templates` and
   `body_zones` and needs no change.
2. `tests/integration/sell-package.test.ts` — the `Axilas x6 / price: 60000`
   fixture becomes `gender:'mujer', size_category:'pequena', session_price:10, bono_price:48`.
3. `scripts/seed-demo.mjs` — the 5 English zones and their `serviceSpecs`
   become real Spanish areas with the new columns; `p.template.price`
   (sales total, line ~247) becomes `p.template.bono_price`.
4. `e2e/global-setup.ts` — constants above; `ensurePackageTemplate` upserts
   the real row instead of inserting a synthetic one.

## Deviations from the proposal

1. **35 zones / 68 templates**, not ~42/~78 — counted exactly from #118.
2. `unique(zone_id, gender)` is a **partial** unique index `where active`
   (decision 1) — a total constraint would make archiving irreversible.
3. The 5 English demo zones are **archived**, not deleted (decision 2) — FK
   `RESTRICT` from `appointments`/`client_packages` blocks deletion.
4. The catalog seed is its **own migration `0013`** (decision 3), splitting
   slice A into A1/A2.
5. Slice **D splits into D1 (tarifas) / D2 (zonas)**; six slices, all under
   400, so no `size:exception` is needed.
6. The E2E fixture becomes a **real catalog row** (`Axilas` mujer, 6 sessions,
   bono 48) instead of a synthetic 3-session `legs` template;
   `E2E_PACKAGE_TEMPLATE_SESSIONS` goes 3 → 6 (decision 7).
7. Tariff ABM is **archive-only** (decision 8), unlike `/configuracion/categorias`,
   because `template_id` is `SET NULL` and a delete would silently orphan history.
8. `maximumFractionDigits: 0` is **dropped**; money uses currency-default
   digits (decision 6), so every existing money assertion string changes.
9. There are **13** formatter call sites, not 11 — the proposal counted only
   `src/`; `e2e/golden-path.spec.ts` and `e2e/caja.spec.ts` are the other two.
10. `clinic_settings` gains **two** columns, `currency` and `locale`
    (decision 9); the proposal left the locale column unnamed.
